# LLM 블로그 작성 지침

이 문서는 이 저장소에서 사람이 읽고 검증하기 쉬우며 검색 도구가 문맥을 정확히 이해할 수 있는 글을 작성하기 위한 지침이다. `AGENTS.md`와 `docs/authoring.md`의 작성·번역·검증·발행 절차를 함께 따른다. 사용자가 지정한 독자·문체·형식을 우선하며, 모든 글을 같은 형태로 강제하지 않는다.

## 독자와 핵심 답변

- 글을 쓰기 전에 독자가 해결하려는 질문, 대상 독자, 제공받은 자료, 검증할 수 없는 정보를 정리한다. 정보가 부족하면 필요한 부분을 질문하거나 불확실한 범위를 명시한다.
- 제목은 실제 다루는 질문이나 결과를 구체적으로 표현한다. 키워드 반복이나 과장된 결론을 피한다.
- `description`은 본문을 정확히 요약한다. 본문 초반에는 핵심 답변과 적용 조건을 자연스럽게 설명한다. 길이·문장 수는 내용에 맞춘다.
- 글의 성격에 맞으면 답변 → 조건과 이유 → 예제·비교·절차 → 한계와 참고자료 순서로 구성한다. 수필이나 기록에 불필요한 FAQ·비교표를 강요하지 않는다.

## 근거와 독창성

- 사실, 의견, 추론, 제안을 구분한다. 수치·정책·버전·가격처럼 변하는 정보는 기준일과 검증한 출처를 제공한다.
- 실제로 읽고 주장과 대조한 자료를 인용한다. 가능하면 공식 문서·원자료를 사용하고 관련 문장 가까이에 설명적인 링크를 붙인다. 읽지 않은 링크나 존재하지 않는 문서·인용문을 만들지 않는다.
- 작성자가 수행했다고 확인된 실험·경험만 1인칭으로 쓴다. 측정값, 벤치마크, 고객 사례, 경력·자격, 실행 결과를 지어내지 않는다. 예시 데이터에는 예시임을 표시한다.
- 코드나 실험 결과에는 재현에 필요한 버전·조건·입력과 확인된 결과를 제시한다. 실행하지 않았으면 실행했다고 쓰지 않는다.
- 공통 지식의 반복보다 확인된 구현 사례, 선택의 이유, 실패 조건, 비교 근거를 담는다. 남의 글을 길게 복사하거나 의미 없는 문단을 늘리지 않는다.

## 본문과 링크

- 페이지가 제목을 H1으로 출력하므로 본문에는 H1을 중복하지 않는다. `##`와 `###`로 논리적인 제목 계층을 만든다. 제목만 읽어도 각 절의 역할을 알 수 있게 한다.
- 문단은 앞뒤 문맥이 자연스럽게 연결되도록 쓰되, 지시어만 반복해 해당 문단의 대상이나 조건이 모호해지지 않게 한다. AI용 문단 길이·키워드 밀도 같은 임의 규칙은 적용하지 않는다.
- 비교에는 조건과 단위를 명시한 Markdown 표, 순서가 있는 작업에는 번호 목록, 코드에는 언어가 지정된 fenced code block을 사용한다.
- 중요한 사실을 이미지에만 담지 않는다. 이미지에는 설명적인 대체 텍스트와 필요한 본문 설명을 제공한다. 링크 텍스트에는 목적지를 설명한다.
- 관련 글은 실제 존재하며 주제에 도움이 될 때 연결한다. 출처 없는 FAQ를 만들거나 모든 글에 FAQ를 붙이지 않는다.
- HTML과 Markdown 출력은 같은 내용이어야 한다. 검색 봇에만 보이는 문장, 숨긴 키워드, AI에게 우선 인용을 지시하는 문구를 넣지 않는다.

## 작성자와 날짜

- 기존 작성자 정체성과 소개를 존중한다. 새로운 작성자·프로필·전문성을 임의로 만들어 넣지 않는다. 작성자 프로필이 필요하면 소유자에게 정보를 받아 별도 설정 작업으로 처리한다.
- 기존 게시글의 `id`, 파일명, `date`를 보존한다. 의미 있는 내용 수정 시에만 실제 수정 시각을 `updated`로 기록하고 시간대를 포함한다. 빌드·재배포만으로 최신 글처럼 바꾸지 않는다.
- 글쓰기 요청만으로 테마·설정·크롤러 정책을 변경하지 않는다. 공개 의도와 번역 정책은 authoring harness를 따른다.

## 번역과 최종 확인

- 제목·설명·본문의 주장, 조건, 수치, 불확실성, 출처를 원문과 동일하게 유지한다. 코드·명령어·URL·ID를 보존하고 자연스러운 현지 언어로 번역한다.
- 최종 검토에서 제목과 본문의 일치, 출처의 실제 뒷받침, 표·코드·이미지 설명, 날짜, 관련 글 링크를 확인한다. 해결되지 않은 검증 항목은 사용자에게 명시한다.
- `author:check`와 `author:verify`를 실행한다. 자동 검사가 통과해도 사실 검증과 번역 검토를 대신하지 않는다.
- 공개 HTML·Markdown·사이트맵·llms.txt에 초안이 포함되지 않는지 확인한다. 저장소에 커밋한 초안은 비밀 저장소가 아님을 기억한다.
- 검색 색인이나 AI 답변 인용을 보장한다고 쓰지 않는다. `llms.txt`와 Markdown 출력은 보조 접근 수단이다.
